# 视觉参考与页面评审

## 1. 参考目的

参考优秀产品是为了学习其设计规律，不是复制品牌界面。优先参考与后台工作场景相近的真实产品页面；营销首页只能作为品牌表达参考，不能直接套用到支付运营后台。

附件讨论中提到的参考方向：

| 产品 | 可观察的设计特征 | 本项目借鉴边界 |
| --- | --- | --- |
| Linear | 信息层级清楚、交互反馈细、视觉克制 | 观察导航、列表密度、状态反馈；不复制其品牌紫色和具体布局 |
| Vercel Dashboard | 简洁、技术信息清晰、强调内容本身 | 观察设置页、表格和状态表达；不把开发者控制台结构照搬到财务后台 |
| Stripe Dashboard | 商业流程完整、交易信息组织清楚、可信度高 | 观察交易详情和资金相关信息的呈现；不复制标志、文案或品牌样式 |
| Raycast | 细节完整、交互反馈利落、品牌表达鲜明 | 只观察微交互和细节完成度，不把强个性动效用于高频核账页面 |

这些是观察对象，不表示最终页面要模仿其中任何一个产品。开始设计时要为每个参考页面记录网址、截图日期、具体观察点和不采用的部分，避免只贴一个品牌名让 AI 自行猜测。

## 2. 建立本项目视觉基线

开发第一个代表页面前，完成以下工作：

1. 选择 2–3 个与交易列表、支付详情或对账任务相近的真实页面作为参考。
2. 写出本页用户、任务、关键字段、主操作、异常路径和预计信息密度。
3. 确定本项目的字体层级、间距刻度、表面、边框、状态、圆角、焦点和图标规则。
4. 在 Figma（如使用）中组织组件、变量和 Auto Layout；明确哪些样式属于已确认的项目令牌。
5. 先完成一张代表页面，再扩展其他模块，避免 AI 每次从空白开始发明一套风格。

设计稿尚未获得星辙品牌规范前，不编造品牌标志或声称某个颜色已经代表星辙。文档中的颜色、尺寸示例只能作为讨论起点，不能直接变成最终品牌令牌。

## 3. 浏览器视觉评审

重要页面需要在浏览器实际渲染后评审，不能把代码成功生成或静态检查通过当成视觉验收。至少检查：

- 常见桌面宽度下的页面层级、内容密度和横向溢出。
- 长订单号、服务商交易号、金额、币种、时间和多行错误信息。
- 加载、空、失败、待核实、禁用和操作完成等真实页面状态。
- 表格对齐、筛选、分页、弹窗/抽屉、键盘焦点和操作结果反馈。
- 与已确认 Figma 目标的排版、间距、尺寸、颜色和组件状态差异。
- 页面是否出现无来源图表、无意义卡片、渐变装饰或占位数据。

根据截图逐项记录明显偏差并修正，再复核同一设计系统在其他代表页面上的一致性。没有 Figma 时，也应以本项目设计原则和已确认令牌作为评审基线，并明确视觉目标尚未经过设计稿对照。

## 4. Figma 与 AI 协作

- Figma 是设计信息的承载工具，不会自动替代设计决策。
- 有 Figma MCP 时，先读取对应页面、组件、变量和布局上下文，再写代码；没有设计稿时不得声称是像素级还原。
- 代码优先复用项目已经确认的组件和令牌，不为每页重新发明颜色、间距和控件状态。
- 编码前先分析页面信息架构和复用方案；复杂页面先说明布局方案和冲突点。
- 最后通过浏览器截图与交互检查页面，记录未验证的状态或屏幕尺寸。

## 5. 页面设计简报模板

新增重要页面时，可在架构设计或功能说明中附上：

```text
页面名称：
主要用户：
用户需要完成的任务：
必须展示的数据：
主要操作：
异常及失败路径：
参考页面及具体借鉴点：
不采用的参考特征：
Figma 页面或组件：
需要验收的状态和屏幕尺寸：
```
