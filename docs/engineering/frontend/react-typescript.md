# React 与 TypeScript 开发规范

## 1. 适用范围

本文约定支付项目 React 运营后台的目录组织、编码方式、API 调用、状态处理、安全和开发阶段验证。

- 技术选择见[技术栈清单](../technology-stack.md)。
- Tailwind、shadcn/ui、主题令牌和视觉规则见[前端样式规范](./visual-style.md)。
- 模块目录见[工程目录结构规范](../directory-structure.md)。
- 本项目使用 React + TypeScript，不同时建设 Vue 前端。

## 2. TypeScript、TSX 和文件规范

- 使用 TypeScript 严格模式；业务代码避免 `any`，暂时未知的数据用 `unknown` 并在 API 边界校验和收窄。
- 页面和组件使用 `.tsx`；纯类型、常量、格式化、API 客户端使用 `.ts`。
- React 函数组件、事件回调、Hook 内局部函数优先使用箭头函数，符合项目偏好的前端写法。
- 导出的组件使用 PascalCase 命名，如 `TransactionDetailPage`；Hook 使用 `use` 开头，如 `useTransactionQuery`。
- Props 使用明确的 TypeScript 类型；避免过宽的可选字段、隐式 `children` 和不必要的通用泛型。
- API 类型对应真实服务端契约，不以可选字段掩盖接口定义缺失；契约变化时同步更新相关类型和说明。
- `const` 优先；只有需要重新赋值时才使用 `let`，禁止 `var`。
- 代码格式由 ESLint、Prettier 和 TypeScript 配置统一，禁止同一文件混用格式风格。

## 3. 前端模块与目录边界

首期模块按支付运营任务组织：

- `transactions`：支付记录、详情和支付状态。
- `exceptions`：待核实交易、通知失败和差异处理。
- `refunds`：星辙退款指令和 Airwallex 退款结果记录。
- `reconciliation`：订单、支付、退款和结算核对。
- `team`：员工账号和权限展示。
- `audit`：操作历史查询。

模块根据真实需求逐步建立：

```text
modules/transactions/
├── api/              # 本模块的请求函数和传输类型
├── components/       # 只在本模块使用的业务组件
├── hooks/            # 本模块的查询和交互 Hook
├── pages/            # 路由页面
└── types/            # 本模块额外的业务类型
```

- 页面组合布局和交互；请求封装放模块 `api/`；模块业务 Hook 放 `hooks/`。
- 私有组件、类型和工具留在模块内；被多个模块真实复用后再提升到 `shared/`。
- `components/ui/` 放 shadcn/ui CLI 添加的基础源码组件；不放业务流程页面。
- `app/` 管理应用入口、路由、身份上下文、全局布局和插件；不放交易业务页面。
- `tools/mock-starpath/` 只用于开发联调，不进入运营后台正式菜单或生产构建。

## 4. React 组件与 Hooks

- React 函数组件只负责清晰的展示和交互职责；页面、业务组件、基础 UI 组件分层。
- Hooks 只在 React 组件或自定义 Hook 的顶层调用；不在条件、循环、事件处理器或普通函数中调用。
- 避免为每个表达式机械使用 `useMemo`、`useCallback` 或 `memo`；只有测量到重复计算或渲染问题时再引入。
- 组件 props 保持最小；避免把整个业务对象无差别传入多个层级。
- 组件协作用 props、回调和明确的 context；不通过全局事件总线传递业务状态。
- 复杂业务规则抽为可命名的纯函数或模块 Hook；不在 JSX 中堆叠金额、权限和状态转换逻辑。
- 不创建没有真实复用需求的 `Base*`、`Common*`、`Universal*` 泛化组件。
- shadcn/ui 源码组件允许按设计系统修改，但更改交互行为时要保留 Base UI 的键盘、焦点和无障碍语义。

## 5. API、服务端数据和异步状态

- Axios 实例集中配置基础 URL、超时、Cookie 凭证、请求标识和通用错误转换。
- 每个业务模块维护自己的 API 函数；页面不直接拼接服务端地址、传输认证头或解释底层 HTTP 错误。
- API 响应按真实契约建立类型；金额与币种成对展示，不在前端以二进制浮点数计算金额。
- TanStack Query 管理服务端列表、详情、缓存和刷新；筛选抽屉开关等临时 UI 状态留在组件或表单。
- 登录身份和少量稳定的全局状态通过明确的 React Context 提供；避免把全部页面状态放进全局 Store。
- 异步界面分别呈现加载、空数据、失败、无权限、处理中和成功状态；失败时提供安全重试或明确下一步。
- 查询条件变化或组件卸载后，避免旧请求结果覆盖新查询；使用查询库的取消与查询键机制。
- 支付发起、通知重试等副作用操作提供处理中反馈并防重复点击；退款仅执行星辙已提交的指令，不添加审批入口。
- 用户回跳页只呈现“正在核实”等体验状态，不能直接在前端判定支付成功；以服务端核实状态为准。
- 交易未知或待核实状态不得被颜色映射成失败；保持业务状态和服务端一致。

## 6. 路由、身份与权限

- 使用 React Router 按业务模块组织路由，页面按需加载。
- 受保护路由检查当前登录身份；菜单和按钮根据角色展示。
- 前端权限只影响界面体验，服务端接口必须重新执行授权。
- 项目所有者只读账号不显示人工重试、备注或退款等操作入口；服务端拒绝时仍需显示无权限反馈。
- 不在 URL 查询参数、浏览器历史或日志中放 API 密钥、会话令牌或敏感个人资料。
- 不在 `localStorage` 或 `sessionStorage` 保存服务端访问令牌；优先使用安全 Cookie 会话。

## 7. 表单、数据格式和可访问性

- 表单字段使用可见标签，不以 placeholder 代替标签；错误和帮助信息靠近对应字段。
- 金额输入只接受协议允许的格式和精度；前端即时提示不能代替服务端校验。
- 日期时间按业务约定显示时区；区分付款发生时间、通知时间和结算时间。
- 金额展示包括币种，支持人民币与美元；界面语言不改变金额和交易状态语义。
- 使用语义化 HTML；弹窗支持键盘交互，焦点打开后进入弹窗、关闭后返回触发控件。
- 图标按钮有可访问名称；状态不能只靠颜色表达，键盘焦点必须可见。
- 分别设计加载、无数据、网络失败、无权限和服务端待核实状态，不允许空白或静默失败。

## 8. 安全和隐私

- Airwallex 或星辙服务端密钥不得进入前端源码、构建产物、公开环境变量或浏览器请求。
- `.env.example` 只写变量名称和非敏感示例；沙盒密钥保存在忽略文件或安全注入环境。
- 生产错误不显示堆栈、内部主机名、SQL 或服务商完整原始错误。
- 不记录完整银行卡信息、认证 Cookie、访问令牌、密钥或未脱敏个人资料。
- 不由前端计算或控制支付结果、权限和退款批准决定。

## 9. 开发阶段质量验证

本节是工程开发流程，不代表产品提供面向星辙员工的测试功能。产品内不建设测试支付、模拟交易、测试模式或测试数据管理。

- ESLint 检查 TypeScript、TSX、React Hooks 和无障碍相关规则；Prettier 固定格式。
- `tsc --noEmit` 在构建前执行，不能只依赖 Vite 的转译结果。
- Vitest 与 React Testing Library 在需要时覆盖纯业务规则和用户可观察交互。
- Playwright 在需要时验证登录权限、交易查询、待核实状态和通知重试等关键链路。
- 浏览器视觉验收检查真实长度的订单号、金额列、焦点、错误反馈和横向溢出。
- 工具和脚本版本见[技术栈清单](../technology-stack.md)及根目录 `README.md`。

## 10. 实现检查清单

- [ ] 页面只承担所属模块职责，没有把请求和领域处理散落在 JSX 中。
- [ ] 类型对应服务端契约，没有用 `any` 隐藏定义缺失。
- [ ] 加载、空、失败、无权限和待核实状态均可理解。
- [ ] 角色操作入口和服务端权限一致。
- [ ] 金额同时显示币种，用户回跳不作为支付凭证。
- [ ] 关键交互支持键盘，焦点、标签和错误信息清楚。
- [ ] 没有把密钥、令牌或敏感数据写入浏览器代码和日志。
- [ ] 页面符合[前端样式规范](./visual-style.md)和[产品界面设计原则](./design-principles.md)。
