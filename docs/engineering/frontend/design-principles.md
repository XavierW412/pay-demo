# 产品界面设计原则

## 1. 目标

本文件定义运营后台应呈现的产品体验，不规定具体 CSS 写法。Tailwind、主题令牌和组件实现规则见 [`visual-style.md`](./visual-style.md)；参考产品及评审流程见 [`visual-references.md`](./visual-references.md)。

界面要让星辙员工能快速查清一笔钱的状态、关联订单、处理责任和下一步动作。品质来自准确的信息架构、排版、密度、细节和一致性，不依赖“高级感”装饰。

## 2. 设计方向

- **产品类型：** 面向支付运营和财务核查的专业后台，不是营销网站，也不是通用数据大屏。
- **视觉性格：** 克制、可信、清晰、有少量可识别的产品特色。
- **主题：** 首期以明亮主题为基线；品牌色和标识等待星辙提供或双方确认。
- **信息密度：** 中高密度。优先保障金额、币种、支付状态、业务订单号、服务商交易号和时间的快速扫描。
- **页面布局：** 由任务决定。交易列表、交易详情、退款记录、异常处理和对账页面可以有各自适合的布局，不强制每页复制同一模板。
- **动效：** 少量、短促、可跳过；用于说明反馈和状态变化，不用持续动画装饰页面。

## 3. 视觉层级与内容规则

1. 每页先明确主要用户、需要完成的判断、主要动作和失败后的路径。
2. 关键字段在列表中易扫读，在详情中能看到完整上下文和关联记录。
3. 金额始终与币种一起展示；支付成功、退款、结算和通知送达分别呈现，不用一个“成功”状态代替全部。
4. 状态至少用文字表达，并辅以适当颜色或图标；颜色不能成为唯一信号。
5. 统计卡片、趋势图和摘要只在能支持实际决策时出现；不生成没有业务来源的数字或图表。
6. 页面要用接近真实的虚构数据校验长订单号、多币种金额、时间和异常描述，不以短占位文案判断布局。
7. 操作按钮要明确说明结果；退款、重试等动作提供确认、处理中、防重复和最终结果反馈。

## 4. 避免的通用模板做法

除非有明确业务理由，不使用：

- 每页固定的欢迎语、四张指标卡和大面积空白。
- 渐变背景、玻璃模糊、发光效果、装饰性网格和大面积彩色阴影。
- 把每一段内容都放进独立圆角卡片造成重复层级。
- 只为视觉填充而添加图表、统计数字、活动流或虚构数据。
- 混搭图标、字体、圆角、阴影和状态颜色体系。
- Emoji 充当核心导航或操作图标，或使用无业务含义的英文占位文案。
- 机械复制 Linear、Vercel、Stripe 等产品的页面布局、标志、配色或品牌素材。

## 5. 可用性和状态

- 重要信息和操作应可用键盘访问，焦点清晰可见。
- 表单标签、错误提示和字段关联明确；弹窗打开后焦点进入，关闭后返回触发位置。
- 页面定义加载、空结果、无权限、失败、待核实和完成等实际需要的状态。
- 异步操作期间避免重复提交；失败提示提供可理解的原因和安全的后续路径。
- 尊重减少动态效果的系统偏好；窄屏时明确说明筛选、详情和宽表格如何浏览。

## 6. 设计决策方法

设计不能停留在“看起来高级”“像 Stripe”这类主观描述。重要页面需要结合真实任务，选取参考界面，制定令牌和组件状态，然后用浏览器实际渲染结果评审。若 Figma 设计稿可用，以已确认稿件为视觉目标；Codex 或其他 AI 生成的页面需要经过实际截图检查和迭代。

本文件只约束设计目标和产品体验。UI 库、样式方案仍以 [`technology-stack.md`](../technology-stack.md) 中的选型状态为准，不应因某个参考页面而自行增加依赖。
