# 支付服务可观测性与技术诊断

## 目标和事实边界

本模块用请求编号、诊断编号、受限前端事件、追踪和聚合指标帮助排查技术故障。诊断事件、日志、指标和告警都是技术线索，不决定支付、退款、星辙通知或结算状态。支付成功仍以服务端核实的 Airwallex 结果为依据；退款仍须星辙批准指令及原有支付侧权限流程。

当前文档依据已写入的接口、数据库迁移和本地观测配置；尚未完成运行中的采集、浏览器角色验收或生产部署。跨系统星辙正式接口仍待星辙确认。

## 关联标识与数据流

- 每个后端请求由过滤器生成服务端请求编号，通过 `X-Request-Id` 响应头返回，并写入请求日志上下文。未处理异常另生成诊断编号，安全错误响应只增加 `diagnosticId`，不公开堆栈或异常正文。响应已经提交时无法保证返回诊断编号。
- 前端错误边界、全局异常和部分请求失败会尝试上报客户端技术事件。成功回执为 HTTP 202 的 `diagnosticId`、`receivedAt`；上报失败时界面仅保留本地编号，不能把本地编号当作服务端已收录事件。客户端不上传原始错误对象、请求正文、支付资料或任意网址。
- 后端在 `diagnostic_incident` 保存事件及服务端计算的指纹；处理动作写 `diagnostic_incident_history`，同时在同一事务写 `operator_audit`。指纹仅保存并建立索引，不出现在列表或详情响应。自动错误以类别、严重度、模块、路由模板和应用版本计算指纹；相同指纹在最近一次服务端接收后 15 分钟内再次上报时，复用同一诊断编号、累计次数并更新最近接收时间。数据库事务锁串行处理相同指纹，避免并发请求创建重复事件。用户主动提交的说明（`USER_REPORT` 或包含用户说明的事件）始终单独保存，避免合并时丢失不同用户的描述。窗口按最近一次上报滑动计算；超过 15 分钟没有新事件时，下次上报创建新记录。已完成事件不会重新打开，后续上报会创建新记录。聚合只更新计数和最近接收时间，摘要、首次发生/接收时间和关联编号保留首次上报内容。
- 追踪采用 OpenTelemetry 标准，经 Spring Boot 管理的导出器向受控 OTLP 接收端发送 span。HTTP 服务端与客户端使用受限 observation 约定：高基数 `http.url` 不写入 span；服务端保留路由模板，客户端只保留已列入白名单的固定路由，未知地址记为 `UNKNOWN`；方法、状态和异常类别为低基数值。三个追踪处理器将原始异常替换成固定消息、无原因和无堆栈的安全异常后才写入 span 事件与状态，异常类别来自固定集合；业务异常对象和业务结果不改动。`traceId` 可作为排查线索，但当前运营页仅显示文本；后端尚无受控 Grafana 追踪链接合同，页面不拼装跳转地址。默认追踪导出关闭、采样率为零；本地启用示例见[部署说明](../../operations/deployment.md#本地观测栈开发验证)。出站至 Airwallex、星辙不传播内部 trace header。

## 匿名事件入口和隐私

`POST /api/v1/diagnostics/client-events` 只接受单个 JSON 对象，不接受查询参数或非白名单字段；白名单字段的值只接受字符串或 `null`，正文上限 8192 字节。字段白名单为 `occurredAt`、`environment`、`appVersion`、`browserFamily`、`category`、`severity`、`module`、`routeTemplate`、`requestId`、`traceId`、`relatedDiagnosticId`、`summary`、`userDescription`。服务端校验时间、版本格式、枚举、预设路由模板和关联编号格式；实际存储环境由服务端部署配置决定，前端传入值不改变它。正式环境拒绝模拟器模块和模拟器路由。

摘要与用户说明经服务端清理并限长；客户端自动上报使用固定摘要，用户说明只在用户主动提供时发送。入口默认按来源地址每分钟 20 次、全局每分钟 300 次，并限制地址桶数；代理地址仅在明确配置可信代理时读取单一受限转发地址。限流使用短期哈希桶，不将原始地址写入事件。生产仍需由星辙决定边界网关保护、容量和滥用处置。

结构化日志只输出固定安全字段，包括时间、级别、服务、环境、请求编号、追踪编号、诊断编号、路由模板、状态码、异常类名和有限堆栈帧摘要；不输出任意日志消息、请求头、正文、Webhook 载荷、认证信息或支付工具资料。当前日志只到应用控制台，Alloy 未配置日志输入，Loki 数据源尚无应用日志。

## 运营查询、权限与处理

运营接口位于 `/api/v1/operations/diagnostics`。列表支持完整诊断编号、最近上报时间范围、模块、级别、状态和分页；响应包含首次发生/接收时间、最近接收时间与聚合发生次数，以及 `diagnosticId`、`environment`、`appVersion`、`browserFamily`、`category`、`severity`、`module`、`routeTemplate`、`summary`、`status`、`handledAt` 和分页信息。日期范围按最近接收时间筛选，日期上界为排他时间。详情另返回事件关联信息、用户说明与处理历史，不返回内部指纹或堆栈。

`STAFF_ADMIN`、`STAFF_OPERATOR`、`TEMP_TESTER` 可查并执行确认、添加备注、完成；`OWNER_READONLY` 可查，但服务端在详情响应中把 `userDescription` 和每条 `history.note` 置为 `null`，且拒绝写入。三种写操作分别调用 `/{diagnosticId}/acknowledge`、`/{diagnosticId}/notes`、`/{diagnosticId}/resolve`，请求体只有 `note`。备注不能为空，文本经过清理并限长；已完成事件不可再次确认或完成。成功操作同时保存诊断历史和统一操作审计，审计正文只含诊断编号与动作，不含备注。前端权限隐藏仅辅助展示，服务端逐请求授权。

这些诊断操作不提供支付核实、通知重试、退款批准或退款执行权限；临时测试员的诊断处理权限也不改变其原有业务权限。

## 指标、告警和恢复

后端为创建收款、支付核实、Webhook 接收与处理、星辙通知、退款执行与核实、对账调度记录固定名称的 Observation/计数器；耗时指标的阶段取固定集合。计数器只使用受限的结果值，指标标签不含订单号、请求编号、用户、金额、异常正文。聚合 Gauge 每 60 秒查询待核实支付、长时间未变化的待处理支付、通知 outbox 积压、未知退款及近 24 小时对账差异；待核实支付数量排除正常等待付款人操作的 `AWAITING_PAYMENT`；查询失败保留最近值，不从监控数值反推单笔支付事实。

`startrail_payment_verification_stale_pending` 只计 Airwallex 支付单中 `CREATING`、`PROCESSING`、`REQUIRES_REVIEW` 且 `updated_at` 超过配置观察阈值未变化的记录，明确排除正常等待付款人操作的 `AWAITING_PAYMENT`。`updated_at` 会随已保存的服务商状态变化更新，即使映射后的内部状态相同；相同状态的重复补查不会更新。默认观察阈值为 15 分钟。该 Gauge 表示本地支付状态记录最近变化时间，不是 Airwallex 付款超时、失败或资金结果。

Prometheus 规则覆盖服务端错误/延迟、支付创建与核实积压、Webhook、通知 outbox、未知退款、对账差异、调度观察和数据库连接池。现有阈值仅是本地技术观察起点，未配置通知接收渠道，也未做生产流量调优。告警只提示进入受保护的诊断入口，不附支付编号、个人信息或错误正文；第三方告警目标需星辙单独批准。

Webhook 接收失败计数覆盖已进入控制器的验签失败和事件接收失败，每次只计一次；请求缺失必要请求头时，框架可能在进入控制器前拒绝，这类请求不进入该计数器，需另看 HTTP 4xx 聚合信息。验签失败不会因事件服务未执行而重复计数。

监控栈停机或导出失败时，先核实业务数据库中的支付、退款、通知 outbox 和对账状态；不能通过修改监控事件推断或修复支付状态。恢复观测组件后，检查采集端可达性、指标抓取、追踪导出和告警规则，再用原业务查询与恢复流程处理真实异常。当前本地栈没有高可用、自动备份或已验证的恢复保证；生产监控数据归属、账号、访问控制、留存、备份、恢复目标和告警渠道由星辙确认。
