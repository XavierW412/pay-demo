# 支付服务运行监控

## 目标和边界

运行监控用于观察支付服务的可用性、耗时和处理积压，不能替代交易记录，也不能改变支付、退款、通知或结算状态。支付成功仍以服务端核实的 Airwallex 结果为依据；退款仍须星辙批准指令及原有支付侧权限流程。

当前代码提供请求关联、安全结构化控制台日志、OpenTelemetry 追踪配置、支付操作指标和 Prometheus 告警规则。本地采集栈尚未完成运行验收，生产采集平台、账号、留存、备份、恢复目标和告警接收渠道由星辙确认。

## 请求日志和错误响应

- 每个后端请求由过滤器生成服务端请求编号，通过 `X-Request-Id` 响应头返回，并写入日志上下文。错误响应只包含业务错误码、面向调用方的安全说明和时间；不返回诊断编号、堆栈或异常正文。
- 结构化控制台日志只输出固定安全字段：时间、级别、服务、环境、请求编号、追踪编号、路由模板、状态码、异常类型和有限堆栈帧摘要。不输出请求头、正文、Webhook 载荷、认证信息或付款资料。
- 当前应用日志只输出到控制台；Alloy 尚未配置应用日志采集，因此 Loki 不含应用日志。需要排查时，应从受控的服务运行日志中按 `requestId` 查找。不得通过日志推断支付结果。

## 追踪和指标

- 追踪采用 OpenTelemetry，由 Spring Boot 管理的导出器向受控 OTLP 接收端发送 span。高基数 `http.url` 不写入 span；服务端保留路由模板，客户端只保留固定白名单路由，未知地址记为 `UNKNOWN`。异常事件仅写入固定安全消息和受限类别。出站至 Airwallex、星辙不传播内部追踪头。
- 追踪默认关闭、采样率为零。本地启用方式见[部署说明](../../operations/deployment.md#本地观测栈开发验证)。生产采样策略及存储访问权限需单独确认。
- 后端为收款创建、支付核实、Webhook、星辙通知、退款执行与核实、对账调度记录固定名称的 Observation 和计数器。指标标签只使用受限结果，不含订单号、请求编号、用户、金额或异常正文。
- 聚合 Gauge 每 60 秒查询待核实支付、长时间未变化的待处理支付、通知 outbox 积压、未知退款和近 24 小时对账差异。待核实支付数量排除正常等待付款人操作的 `AWAITING_PAYMENT`；查询失败时保留最近值，不能从监控数值反推单笔支付事实。
- `startrail_payment_verification_stale_pending` 只统计 `CREATING`、`PROCESSING`、`REQUIRES_REVIEW` 且 `updated_at` 超过观察阈值未变化的 Airwallex 支付单。默认阈值为 15 分钟；它反映本地记录最近变化时间，不表示 Airwallex 付款超时、失败或资金结果。

## 告警和恢复

Prometheus 规则覆盖服务端错误与延迟、支付创建与核实积压、Webhook、通知 outbox、未知退款、对账差异、调度观察和数据库连接池。现有阈值仅为本地技术观察起点，尚未配置告警通知渠道，也未按生产流量调优。

Webhook 接收失败计数覆盖进入控制器后的验签失败和事件接收失败，每次只计一次。缺少必要请求头、在进入控制器前被拒绝的请求不会计入该计数器，需结合 HTTP 4xx 聚合信息判断。

监控栈停机或导出失败时，先核实业务数据库中的支付、退款、通知 outbox 和对账状态；恢复观测组件后再检查采集端可达性、指标抓取、追踪导出和告警规则。监控数据不能直接改写交易状态。本地栈没有高可用、自动备份或已验证的恢复保证。

## 历史数据库迁移

V121 至 V123 曾用于技术诊断事件表。迁移文件保留在版本历史中以维持 Flyway 校验兼容；当前服务已移除对应读写接口，不再新增事件或处理历史，既有数据库记录也未删除。若需清除历史表和数据，应另行确认保留要求并制定数据库迁移。
