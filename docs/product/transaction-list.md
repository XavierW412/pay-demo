# 交易列表页面需求（首版建议）

## 1. 目标与状态

页面供星辙运营员工快速定位订单，并区分支付是否完成、结果是否通知星辙、退款和资金结算处于什么状态。项目所有者可查看同一页面，但只能只读。

本文是基于已确认产品范围整理的页面级建议。业务责任和记录范围来自[产品说明](./product-spec.md)；星辙接口字段、Airwallex 字段及状态映射仍待正式资料确认。Figma 版使用虚构数据，不构成接口契约。

首版可编辑原型：[在 Figma 中查看交易列表](https://www.figma.com/design/qBIDjicAvYyRdC065a4SQy/%E6%98%9F%E8%BE%99%E6%94%AF%E4%BB%98%E8%BF%90%E8%90%A5%E5%8F%B0%E5%8E%9F%E5%9E%8B?node-id=3-4)。画板上方和下方的注释不属于产品界面；原型使用的 Noto Sans SC 字体、颜色和状态样例都是临时视觉方向，仍待评审。

## 2. 页面结构

1. 页面标题“交易记录”，简短说明此处用于查询支付链路与处理异常。
2. 一行主搜索和筛选：订单/支付单号搜索、创建时间范围、支付状态。
3. 可展开的“更多筛选”：星辙通知状态、退款状态、资金结算状态。
4. 交易表格；不放没有真实决策用途的统计卡片和图表。
5. 分页和结果数量。

## 3. 表格字段

| 顺序 | 显示字段 | 内容与来源 | 首版展示方式 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 星辙订单号 | 星辙业务订单的关联编号 | 主文本，可复制；同一列第二行显示本项目支付单号 | 页面需要已确认；具体 API 字段待星辙确认 |
| 2 | 金额 | 星辙订单传入的金额与币种 | 金额和币种始终同时显示；本项目不编辑 | 已确认产品边界；精度和格式按契约 |
| 3 | 支付状态 | 本项目根据 Airwallex 可信结果核实后的支付状态 | 用文字和状态颜色共同表示；“待核实”与“失败”不得混为一类 | 状态分组建议；映射待 Airwallex 契约确认 |
| 4 | 星辙通知 | 该支付结果是否、何时送达星辙 | 独立显示“待发送/发送中/已送达/需处理”等归一状态 | 需要独立追踪；具体状态及措辞待接口设计 |
| 5 | 退款状态 | 是否存在星辙已批准并由本项目执行的退款记录 | 无退款记录显示“无”；存在时展示归一处理状态 | 需要独立追踪；部分退款规则待星辙确认 |
| 6 | 资金结算 | Airwallex 结算数据与该笔交易的核对状态 | 显示“待结算/已匹配/需核对”等归一状态 | 需要独立追踪；数据源和状态待账户能力确认 |
| 7 | 创建时间 | 本项目收到订单并创建支付记录的时间 | 按项目统一时区展示；排序默认最新优先 | 建议；统一时区和精度待工程配置 |
| 8 | 操作 | 打开交易详情 | 员工和只读所有者均可查看；列表不直接执行退款或改支付状态 | 已确认角色边界 |

星辙订单号和本项目支付单号放在同一单元格，但必须清楚标注各自身份。Airwallex 交易编号在交易详情中作为第三方核查标识展示，不挤进列表主列；列表搜索仅支持当前可确认的订单号和支付单号。具体搜索范围可以在拿到接口标识后扩展。

## 4. 查询和筛选

- 主搜索：星辙订单号或本项目支付单号；完整、部分编号均可查找。搜索行为及大小写/精确匹配策略由实现架构确定。
- 创建时间：开始和结束时间范围；默认不预设固定历史区间。
- 支付状态：按归一后的支付状态筛选。状态清单等 Airwallex 状态机设计时再固定。
- 更多筛选：星辙通知、退款、资金结算状态。
- 默认排序建议按创建时间倒序；不提供目前没有依据的付款人、地区、卡种、设备或商品筛选。

## 5. 状态展示规则

- 支付、通知、退款、结算是四个独立状态，不拼成一个“交易状态”。
- “待核实”意味着信息不足，不能用红色失败状态代替，也不能因此显示成功。
- 支付成功不表示资金已结算；结算状态单独跟踪。
- 没有退款记录时明确显示“无退款”，不要留空让人误以为数据丢失。
- 所有颜色都配文字；具体状态、颜色和图标需与前端主题令牌对齐。
- 失败、待核实或差异应易于定位，但不在列表中提供修改资金状态的操作。

## 6. 权限和操作

- 所有角色可以按权限查看列表并进入详情。
- 项目所有者账号只读；不出现操作按钮。
- 员工可在详情页按授权执行查询 Airwallex 状态、重试支付结果通知或补充异常备注。每次操作需确认权限并留审计记录。
- 退款只能由星辙批准后发送指令；列表不提供独立的退款审批/发起操作。
- 页面不提供测试付款、模拟交易开关或测试数据管理入口。

## 7. 原型示例数据约束

- Figma 页面需在画板边缘或明显注释中标记：**“原型示例数据（非真实交易）”**。
- 示例订单号和支付单号使用明显虚构的演示值；不得表示为正式编号格式。
- 允许用人民币和美元示例来检查金额排版；示例值不代表账户已开通相应生产能力。
- 可展示“待付款、处理中、已支付、待核实”等示例状态来校验视觉区分；它们是原型状态样例，不是最终 API 枚举。
- 不展示付款人姓名、邮箱、手机号、银行卡信息、支付方式、地区、产品名称、风控结论、手续费、汇率等未确认字段。

## 8. 需要后续确认

- 星辙业务订单号与本项目支付单号的真实命名及是否都可提供给运营人员。
- Airwallex 支付标识、支付/退款状态和结算数据对应的正式字段与状态映射。
- 通知状态、退款状态、结算状态的精确枚举和显示文案。
- 时间展示时区、创建时间来源、列表默认查询区间和分页规则。
- 哪些员工角色可以查看全部交易或执行详情页内的重试/备注动作。

在这些项目确认前，页面可以用清楚标记的模拟数据完成视觉原型；实现时不得把原型编号和状态枚举当作生产协议。
