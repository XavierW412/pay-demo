# 交易详情页面需求（首版方案）

## 1. 页面目标与状态

详情页帮助星辙员工回答四件事：这笔支付对应哪张星辙订单、Airwallex 实际状态是什么、结果是否送达星辙、是否存在退款/结算差异。页面也提供少量经授权的查询、通知重试和异常备注操作。

这是根据[产品说明](./product-spec.md)和已认可的[交易列表方案](./transaction-list.md)形成的首版设计；字段集合是建议，外部 API 原始字段、状态枚举和时间来源待正式资料确认。Figma 示例数据仅用于原型评审。

可编辑原型：[在 Figma 中查看交易详情](https://www.figma.com/design/qBIDjicAvYyRdC065a4SQy/%E6%98%9F%E8%BE%99%E6%94%AF%E4%BB%98%E8%BF%90%E8%90%A5%E5%8F%B0%E5%8E%9F%E5%9E%8B?node-id=5-5)。画板注释不属于产品界面；账号角色、订单编号、Airwallex 编号、事件时间与状态均为虚构示例。

## 2. 页面分区

1. **页面头部**：返回交易列表、星辙订单号、支付状态；员工视图展示可用操作，所有者视图显示“只读”。
2. **支付摘要**：星辙业务订单号、本项目支付单号、Airwallex 交易编号、订单金额/币种、记录创建时间及可获得的支付完成时间。
3. **链路状态**：分别展示支付、通知星辙、退款、资金结算四种状态及最近更新时间；不能用一个总状态覆盖。
4. **处理时间线**：按时间展示订单接收、收款请求创建、Airwallex 状态核实、通知发送/重试等已记录事件；说明事件来源和结果，不展示密钥、卡号或完整请求头。
5. **退款记录**：存在星辙批准的退款指令时，展示本项目执行结果和关联标识；没有记录时清楚显示“暂无退款记录”。退款审批仍归星辙。
6. **结算核对**：在 Airwallex 提供相应数据后，展示关联结算标识、核对状态和可获得的结算时间；数据不足时显示待结算/待核对，不推算手续费或汇率。
7. **操作审计**：展示员工操作、时间、结果和必要备注；项目所有者只读查看。

## 3. 首版字段建议

| 区域 | 字段 | 规则/来源 | 状态 |
| --- | --- | --- | --- |
| 支付摘要 | 星辙业务订单号 | 用于回查星辙业务订单 | 产品需要已确认；外部字段待确认 |
| 支付摘要 | 本项目支付单号 | 本项目生成的内部关联编号 | 建议作为必备追踪标识 |
| 支付摘要 | Airwallex 交易编号 | 用于在 Airwallex 侧定位支付 | 关联需要已确认；实际编号类型待账户/API 确认 |
| 支付摘要 | 订单金额与币种 | 使用星辙订单传入的原始金额和币种 | 产品边界已确认；格式/精度按契约 |
| 支付摘要 | 创建时间、支付完成时间 | 分别指本项目建单与可信支付完成时间 | 支付完成时间来源和时区待架构确认 |
| 链路状态 | 支付、通知、退款、结算状态 | 独立记录和显示 | 状态映射待 Airwallex 与星辙契约 |
| 链路状态 | 最近更新时间 | 对应状态最近变更的记录时间 | 建议；时区待统一 |
| 退款记录 | 退款金额/币种、退款状态、退款关联编号 | 仅展示星辙指令触发且本项目实际记录的退款 | 是否部分退款、字段名和规则待星辙确认 |
| 结算核对 | 结算关联编号、结算状态、可获得的结算时间 | 依据 Airwallex 实际结算数据 | 待账户能力和数据源确认 |
| 操作审计 | 操作者、动作、时间、执行结果、备注 | 由本项目留痕 | 产品范围已确认；精确审计字段由架构设计 |

## 4. 员工和所有者的可见/可操作差异

### 星辙员工

- 可查看其权限范围内的支付和关联记录。
- 支付状态未知或长时间未更新时，可发起“查询 Airwallex 状态”；查询结果仍需服务端核实，不能直接人工改成功。
- 星辙通知失败或待重试时，可按权限“重试支付结果通知”。执行前弹出确认框，明确会向星辙发送哪笔订单的支付结果；用户确认后显示处理中，成功/失败后展示结果并写入操作审计。
- 可填写异常处理备注；备注只增加留痕，不改变支付、退款或结算状态。
- 不得从详情页批准星辙业务退款、创建新的退款指令、改支付成功状态或编辑原始金额/币种；`STAFF_ADMIN` 可确认已通过校验且等待确认的星辙退款指令，本地沙盒临时测试员也可执行此操作。

### 项目所有者

- 可查看完整支付、退款、通知、结算和员工操作记录。
- 页面标注“只读”；隐藏所有查询触发、通知重试和备注操作，不只是禁用按钮。

## 5. 空态、异常与隐私

- 支付结果待核实时明确解释“状态尚未核实”，不使用失败样式。
- Airwallex/星辙记录未返回时写明“暂无记录”或“待同步”，不把空值当成失败。
- 通知重试必须防重复提交，并显示操作人、时间和结果。
- 异常不提供手工编辑资金状态的入口；无法自动核实时保留证据并引导星辙处理。
- 不展示完整卡号、安全码、认证令牌、API 密钥、完整 Webhook 请求头、无必要的个人资料。
- 付款人姓名/联系方式、支付方式、商户费用、汇率和风控信息因当前缺少产品依据而不展示。

## 6. 原型标注

Figma 画板标注“原型示例数据（非真实交易）”。星辙订单号、支付单号、Airwallex 编号、时间、退款和结算状态均使用虚构值。状态样例用于评审信息层级，不构成最终业务状态或接口枚举；只读所有者视图使用说明注释表达，不新增产品内角色切换或测试开关。

## 7. 后续需要确认

- 星辙订单/支付/退款接口中真实编号的名称、长度和查询能力。
- Airwallex 可返回的 Payment Intent/支付编号、Webhook/查询状态及结算明细。
- 通知失败时允许谁重试、重试频率和防重规则。
- 员工实际角色与每类订单的访问范围；所有者只读权限不变。
- 退款和结算记录是否会多笔关联、部分退款规则，以及相应字段。
- 操作日志展示范围、备注保留期和脱敏规则。
