# 甲方临时测试账号设计

## 文档状态

设计已在对话中确认。临时测试账号功能按本文档实施。

## 目标

为甲方测试人员提供一组可立即登录星辙支付运营后台的临时用户名和密码。账号从生成时开始有效 6 小时，到期后服务端拒绝登录和后续运营请求。测试人员可以验证完整的运营操作流程，但不能管理员工。

临时账号只供本地开发和 Airwallex 沙盒联调。正式环境不得生成临时账号，也不得把沙盒测试账号作为生产人员账号。

## 用户与权限

- 由已登录的 `STAFF_ADMIN` 在“员工与权限”页面生成临时账号。`OWNER_READONLY` 仍保持只读。
- 新角色为 `TEMP_TESTER`，权限与员工管理员的运营权限一致，但排除员工邀请、邀请撤销、员工启用/停用和临时账号生成功能。
- 临时测试员可以查看运营数据、核实支付与退款状态、重试允许重试的通知、添加交易备注，并确认已获星辙批准且支付侧核验通过的退款。
- 退款确认会调用当前配置的 Airwallex 沙盒接口，因而可能实际产生沙盒退款记录。账号不能批准星辙业务退款，也不能绕过退款核对流程。
- `STAFF_ADMIN` 可以在六小时到期前提前停用临时账号。临时测试员不能停用自己或其他账号。

## 账号生成和使用流程

1. 管理员点击“生成临时测试账号”。服务端校验当前运行在 `local` 环境，且 Airwallex 配置明确指向沙盒；任一条件不满足时拒绝生成。
2. 服务端生成不可预测的用户名和高强度随机密码，设置角色 `TEMP_TESTER`、启用状态和 `expires_at = created_at + 6 hours`。
3. 数据库只保存密码的 BCrypt 摘要。用户名、初始密码和到期时间仅在生成成功的响应中返回；页面只临时显示本次结果，支持复制，不写入浏览器持久存储。
4. 管理员通过可信渠道把这组凭证交给甲方测试人员。系统不自动发送账号或密码。
5. 测试人员使用运营登录页登录并执行授权范围内的操作。每个已认证运营请求都重新核验账号是否仍有效。
6. 超过 `expires_at` 后，登录失败；已有会话的下一次请求返回未授权并清除会话。账号状态在列表中显示为已过期，不再允许操作。
7. 管理员可在到期前提前停用，服务端立即拒绝该账号后续请求并使其现有会话失效。

## 凭证与审计安全

- 密码使用密码学安全随机数生成，至少 128 位随机熵；不接受客户端自定义密码或延长时长。
- 初始密码仅生成响应返回一次，不写数据库、应用日志、审计详情、网址、浏览器持久存储或分析事件。管理员关闭凭证展示后无法再次取回密码；如遗失，先停用旧账号再生成新账号。
- 创建审计记录包含操作人、账号标识、角色、生成时间、到期时间和结果，不包含密码。
- 提前停用写入独立审计记录。到期由服务端判断，不依赖浏览器计时器或定时清理任务。
- 不向临时账号授予邀请、员工目录修改、账号启停等权限。服务端授权必须实施此限制，前端隐藏按钮不能作为权限边界。

## 数据与接口设计

### 数据库

在 `operator_account` 增加可空 `expires_at TIMESTAMPTZ`：永久账号为空，临时测试账号写入固定过期时间。账号角色约束增加 `TEMP_TESTER`。保留过期账号和审计历史，不删除账号行；过期状态由 `active` 与 `expires_at` 组合推导。

### API

- `POST /api/v1/operations/team/temporary-accounts`：仅 `STAFF_ADMIN` 可调用，仅本地沙盒配置可用。请求不接受权限、密码和到期时间参数。成功时一次性返回 `{ accountId, username, initialPassword, role, expiresAt }`。
- `PATCH /api/v1/operations/team/accounts/{accountId}/active`：允许管理员停用 `STAFF_OPERATOR` 和 `TEMP_TESTER`，禁止修改自己的状态、管理员账号或所有者账号。
- 员工账号列表增加 `expiresAt` 和账号类型/状态信息，以明确区分永久员工、临时测试账号、已过期和已停用。

每次成功的生成请求都创建新账号，不能返回旧账号的初始密码。页面在请求处理中禁用生成按钮；若响应未到达而账号已经创建，管理员可从账号列表找到并停用该账号，再重新生成。

## 到期与授权实施边界

- 登录认证读取 `active` 和 `expires_at`；过期账号不能建立新会话。
- 运营账号状态过滤器在每个已认证运营请求中核验账号 `active` 且未过期，过期后清理会话并返回统一未授权响应。
- `TEMP_TESTER` 可访问与 `STAFF_ADMIN` 相同的非员工管理运营接口；员工邀请、员工目录管理和账号状态变更接口只允许 `STAFF_ADMIN`。
- 临时账号创建端点只对 `STAFF_ADMIN` 暴露，并在服务端同时校验 `local` 环境和 Airwallex 沙盒主机；生产配置必须拒绝该操作。

## 页面交互

- 在“员工与权限”页新增“生成临时测试账号”操作，并说明权限、6 小时有效期及退款确认可能产生沙盒退款。
- 生成成功后以明显的安全提示展示用户名、一次性密码和准确到期时间，提供复制凭证操作。离开页面或关闭结果区后不再从服务端恢复密码。
- 员工列表显示“临时测试员”标签、过期时间、剩余有效期或过期状态；管理员可提前停用。
- 普通员工和临时测试员看不到账号生成、员工邀请及停用控件；后端仍独立拒绝越权请求。

## 方案取舍

选择独立 `TEMP_TESTER` 角色、账号过期时间和一次性凭证展示。复用员工账号表与登录系统，避免再造认证体系；独立角色避免把员工管理员权限错误地完整授予甲方测试人员。六小时固定策略简单可审计，服务端每请求校验使账号过期不依赖后台定时任务。

不复用员工邀请链接：邀请要求对方自行注册，且不能满足直接交付用户名和密码。不给所有员工账号统一设置短过期时间，避免影响星辙正式员工账号。

## 主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 临时凭证被转发或泄漏 | 高熵随机密码、一次展示、仅管理员可生成、审计不含密码、可提前停用 |
| 过期账号仍持有后台会话 | 登录时和每次运营请求都校验 `expires_at`，过期即清会话 |
| 测试人员误触退款执行 | 页面明确提示沙盒退款副作用；继续经过原有星辙批准与支付侧核对，不新增绕过操作 |
| 临时权限进入生产 | 生成 API 在服务端限制 `local` 配置和 Airwallex 沙盒主机，生产配置明确拒绝 |
| 角色权限配置遗漏 | 后端路由逐项授权；只有员工/邀请管理路由拒绝 `TEMP_TESTER`，不依赖前端隐藏 |

## 验收条件

1. `STAFF_ADMIN` 可在本地沙盒生成账号，页面只显示一次用户名、初始密码和到期时间。
2. 数据库与日志中无明文密码；创建和提前停用均有可追溯审计记录。
3. `TEMP_TESTER` 可完成获准的运营操作，包括管理员确认已核验通过的退款；其请求不会绕过现有业务和资金校验。
4. `TEMP_TESTER` 访问邀请、员工目录变更和账号启停接口均被服务端拒绝。
5. 到期后新登录与已有会话请求均失败；管理员提前停用后已有会话立即失效。
6. 非 `local` 配置或非 Airwallex 沙盒主机无法生成临时账号。
7. 永久员工、管理员和所有者的既有登录、角色及会话行为不被临时账号逻辑改变。

## 暂不包含

- 生产环境临时账号。
- 自定义权限组合、客户端指定用户名/密码/有效时长。
- 自动给甲方发送账号凭证。
- 自动删除过期账号或重置账号操作历史。
- 新增模拟付款、测试交易或跳过星辙批准的退款入口。
