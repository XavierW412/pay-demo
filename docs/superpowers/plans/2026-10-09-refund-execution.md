# 首期退款执行计划

1. 核对产品边界、现有星辙签名和通知链路、支付单状态与 Airwallex 官方退款接口。
2. 以独立退款入站密钥接收星辙已批准指令；原始正文验签，按稳定指令编号幂等。
3. 用单独退款表记录状态并在支付单行锁下预留金额，校验原支付与 Airwallex 捕获金额，防止并发部分退款超额。
4. 调用 Airwallex 创建退款，并以查询任务核实受理、接受、对账成功和失败；不确定结果保持占用，不重建新请求。
5. 将状态事件写入现有通知队列，与星辙真实契约相关字段继续标记为提议。

风险与取舍：本地表先提交再调用远端，使网络请求不占数据库事务，但存在远端成功后本地尚未保存服务商编号的窗口；通过稳定 `request_id` 和列表查询恢复。保持未知金额占用可能需要人工对账，但可避免重复退款。真实星辙接口、退款业务政策和账户能力未提供，不能宣称生产可用。
